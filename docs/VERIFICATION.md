# Document verification: implementation

- **Verification ID**: 128-bit random (UUID without dashes, 32 hex chars), generated by the server (`Util.uuid`) when a document is issued. It is not derived from student, amount or date, so it cannot be guessed or enumerated.
- **Registry**: tab `DocumentVerification` holds ID, document number, type, version, `supersedes`, status (`valid`/`revoked`), issue/revoke info, a SHA-256 hash of the canonical content snapshot, and the snapshot itself (the data needed to reprint exactly what was issued).
- **QR** (byte mode, ECC M): the URL `<public base>#/verify/<ID>`. **PDF417** (byte compaction, ECC level by size): the bare ID only. Both are vector shapes in the PDF with a white quiet-zone backing; the watermark is drawn behind content and never over the codes.
- **Public check** (`verify.check`, no login): returns `status`, `centreName`, `docType`, `issueDate`, `version`, `isLatest` (and the document number only if enabled in Settings). Unknown, malformed and missing IDs all return the same "invalid" shape; requests are rate-limited per minute.
- **Versioning**: re-issuing with identical content returns the same ID and version (a reprint). Changed content creates version n+1; older versions stay valid but show "a newer version has been issued". Receipts are immutable and are revoked only by reversing the payment.
- **Revocation**: status becomes `revoked`, with reason and actor in the audit log; the old PDF still scans and says REVOKED.
- A PDF cannot be proven authentic by the PDF alone; the registry is the source of truth. A copy of a valid document will also verify as valid. The check confirms that the centre issued that document, not who is holding it.
